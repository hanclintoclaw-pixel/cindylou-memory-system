# U4 public CLI canary candidate

Generated by `openai/gpt-6.1-sol`, high, 2026-10-31.

## Scope

`unification.canary_cli` is a separate, default-off **public campaign** caller.
It exercises the shared `MemoryService` hybrid search and the existing native
reader's generation-checked bounded get/health. It does not replace `cindylou`,
install a shell command, expose an HTTP endpoint, change a service, prepare an
index, import facts, or alter a source approval. Native searches can update the
**explicitly supplied isolated partition's** index/recall state.

This stage is caller preparation, not completed U4 deployment. The reviewed
partition still covers only two public sections. Search retrieves candidates;
neither a score nor a successful get establishes answer correctness. Private
captures and SR3 specialists remain separate established interfaces; this first
campaign caller does not route to them or silently fall back on failure.

## Invocation

From the isolated worktree, using the exact registry and partition recorded in
private STATE:

```sh
python3 -m unification.canary_cli --enable-canary \
  --registry "$REGISTRY" --partition "$PARTITION" search --q 'Tom Erlichman'
python3 -m unification.canary_cli --enable-canary \
  --registry "$REGISTRY" --partition "$PARTITION" \
  get "$DOCUMENT_ID" --revision "$FULL_FILE_SHA256" --start-line 1 --lines 20
python3 -m unification.canary_cli --enable-canary \
  --registry "$REGISTRY" --partition "$PARTITION" health
```

Registry/partition paths are local trusted configuration, not an authorization
interface for remote clients. Audience is fixed public, even for an operator.
Public inputs outside the campaign domain are refused. Unknown documents,
mixed-page aliases and unapproved/private sections retain native denial.

Reads require the exact SHA-256 returned by search. Bounds are section-relative;
citations/`source_line` refer to the original authoritative file. The native
reader validates the entire supplied source generation before and after I/O,
and closes/reaps its child after every command, including failures.

`--min-score` defaults to zero (neutral candidate filtering). The old 0.30
experiment is not a deployment recommendation or answer-confidence gate.
`--timeout` bounds each native protocol exchange, not total process wall time;
startup, the requested operation and shutdown are distinct exchanges. Hosts
needing a strict total budget must add an outer process deadline and termination.

Exit codes: success/healthy empty `0`, usage/disabled `2`, denied `3`, stale `4`,
unavailable `5`. Unavailable/stale/denied never become lexical success. There is
no write/promotion verb, audience override, server mode or automatic legacy
fallback. Configuration errors are sanitized instead of printing private paths.

## Verification and rollback

```sh
python3 -m unittest discover -s tests/unification -v
node --test tests/unification/native_contract.test.mjs
python3 scripts/memory_unification_canary_verify.py \
  --registry "$REGISTRY" --partition "$PARTITION" --output-root "$PRIVATE_RECEIPTS"
```

Caller tests cover disabled-before-I/O, public context, exact revision/bounds,
generation revocation before launch, missing state, backend death without
fallback, status preservation and child teardown. Existing native tests cover
in-flight revision/revocation, warnings, unsafe configuration, runtime pin,
negative reads and timeout/restart behavior. The actual CLI verifier checks
search/get on both reviewed sections, denial, stale revision, oversized reads,
health, unchanged authority/code/config hashes and default-off rollback.

Rollback is to stop passing `--enable-canary` (or stop invoking this separate
module). Verification checks default-off behavior before and after enabled
calls. No live config/DB restore, source deletion, capture loss or daemon restart
is involved. Full command timings include fresh Python/Node/native startup and
shutdown; three samples per entity are not a warm service p95 or live-game SLA.

Exact observed results, failures and private receipt path belong in STATE/JOURNAL.
No private passages or runtime configuration values belong in this document.

Observed preparation result: **175 Python + 3 Node tests pass**; the actual
two-section CLI run passes **14/14 checks**, with all observed authority, code,
registry, projection-manifest and selected configuration hashes unchanged.
