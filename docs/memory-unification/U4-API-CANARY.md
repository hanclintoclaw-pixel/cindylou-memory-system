## Concrete candidate

`unification.canary_api` starts a foreground-only, default-off HTTP server on
**127.0.0.1 only**, on an explicitly supplied unprivileged port. There is no
`--host`, remote binding, automatic startup, daemon installation or old-service
restart. Main validates the complete reviewed generation before binding.

- `GET /v1/health`: authenticated native dependency check.
- `POST /v1/search`: `query`, optional integer `limit` (1–30).
- `POST /v1/get`: section `doc_id`, exact full-file `revision`, optional relative
  `start_line` and `lines` (1–200). Entire output is bounded by the shared reader.
- Every route uses the same fixed public campaign registry/partition and shared
  executor as the CLI. No request can set audience/domain/registry/partition.
- No facts, capture, promotion, rebuild, restart, session or administrative route.
  There is no legacy fallback or automatic source approval.

Every endpoint requires `Authorization: Bearer …`. The token is read at startup
from an owner-readable, owner-owned regular file, without symlink following and
with no group/world permission bits. It grants access to this public route, not
operator/private records. Tokens and HTTP headers are never logged. Browser
Origin/Fetch-Metadata requests are denied; no CORS capability is installed. This
is an API-client canary, **not browser integration** or a replacement for the
legacy `0.0.0.0:8091` API. Existing API consumers have not been redirected.

Request bodies are capped at 8,192 bytes. Malformed/unknown fields, transfer
encoding and ambiguous length headers are refused. Responses are no-store.
Authentication precedes body parsing/backend calls. Denied/stale/unavailable
remain HTTP 403/409/503; invalid input is 400. Missing route authentication is
401. Unknown authenticated routes are 404. Backend errors do not expose paths.

Native calls are serialized. Each fresh request closes its native reader on
success/failure; idle socket reads have a five-second timeout and native
protocol exchanges have a five-second timeout. This is **not a total request
deadline, production p95, concurrency/load claim or production availability SLA**.
Coverage stays the same two reviewed sections, with provisional labels intact.

## Underlying module recipe

The pinned launcher supplies the equivalent of:

```sh
python3 -m unification.canary_api --enable-canary \
  --registry "$REGISTRY" --partition "$PARTITION" \
  --token-file "$OWNER_ONLY_TOKEN_FILE" --port 18091
```

Check port availability before deployment; never evict another listener.
The token stays private and is not put in a command line, git, a URL or Discord.
Starting this foreground candidate does not require a shell-profile or launchd
change. Any later persistent service must pin code/config and preserve the same
scope; such an installation is not part of this tested foreground candidate.

Rollback: stop this separate foreground process (Ctrl-C), then omit
`--enable-canary`. The listener closes. No old-service restore, source deletion,
capture loss or DB restore is involved. Stopping disables access while the
listener is down. To revoke a route token, replace the private token file and
restart; restarting with the same token does not invalidate it. File replacement
alone does not update a running instance.
Source/revision revocation is checked on every request independently.
